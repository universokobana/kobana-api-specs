Start integrating now in a sandbox environment and contract only when you're ready

This is the testing environment for API usage. If you don't know what this is, read about the [concept of Sandbox on Wikipedia](http://en.wikipedia.org/wiki/Sandbox_(software_development)).

For security reasons, the sandbox environment is on servers completely separate from the production environment. No data is shared between environments. You need to create an account in the sandbox environment as well as in the Production environment and each account will have its data isolated.

:::info

- The sandbox environment has servers with fewer resources and therefore is slower than the production environment. Do not take this environment's performance into account.
- Search filters in the sandbox environment on some screens may not work due to resource limitation in the sandbox environment.

:::

The system version in the Sandbox environment is always the same version as the Production environment.

# Getting Started

To start using the Sandbox environment, you need to create an account in this environment.

[Create account in Sandbox environment](https://app-sandbox.kobana.com.br/users/sign_up)

After creating the account, you will be able to use the Sandbox environment the same way you will use the Production environment. Read about authentication to get started.

No account validation is performed in this environment and shortly after account creation, you will be able to use the API.

# Restrictions

The Sandbox environment should not be used for the purpose of performing real operations. It should only be used to test your system's integration with Kobana's API, without affecting your real account data.

:::info

The Sandbox environment does not communicate with banks.

:::

For this reason, this environment has some restrictions. They are:

## Bank Slip Generation

- Agency and Account in generated bank slips will be changed to 1 and 2.
- Instructions for the cashier in the generated bank slip will come with the message: "SIR/MADAM CASHIER, WE DO NOT AUTHORIZE RECEIVING THIS BANK SLIP".
- Agency and Account in generated remittances will be changed to 1 and 2.
- Bank slips and remittances should not be used for homologation purposes with the bank.

## Environment Cleanup

For security reasons, all data is automatically deleted from the Sandbox environment on Mondays, Wednesdays and Fridays between 02:00 and 03:00 in the morning Brasília time.

## Events

You can simulate events to test webhooks.

## Bank Slip

In the bank slip view screen you can enter payment information and mark as overdue which are only presented in the sandbox environment, on the bank slip screen. This way the events `bank_billet.paid` and `bank_billet.overdue` are generated for each action respectively.

## Payment

Do not pay a charge generated by the Sandbox environment under any circumstances.

When you log in to the Sandbox Environment it's possible to emulate the payment of a charge.

## Fraud

The barcodes of test bank slips and QR Codes of Pix generated by the Sandbox environment are not valid and must not be paid under any circumstances.

The use of charges generated in the Sandbox environment is considered fraud. No charge generated in this environment can be disclosed or sent to third parties.

It is the responsibility of the customer to prevent the charge generated in this environment from being disclosed in any way.
